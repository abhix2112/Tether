**Your hands-on task (from LEARNING.md §8):** run the llm-d simulator, send one long prompt twice, and
watch `usage.prompt_tokens_details.cached_tokens` and time-to-first-token change.

```bash
# 1. Start the simulator (pinned image; no GPU, no tokenizer download).
docker run -d --name tether-sim0 --network host -e POD_IP=127.0.0.1 \
  ghcr.io/llm-d/llm-d-inference-sim:v0.11.2 \
  --model test-sim-model --port 8000 --enable-kvcache true \
  --block-size 64 --kv-cache-size 256 --max-model-len 16384 \
  --latency-calculator per-token --prefill-overhead 20ms --prefill-time-per-token 1ms \
  --inter-token-latency 5ms --seed 1 --mode random

# 2. Build a 2,000-word prompt.
python3 -c 'import json; print(json.dumps({"model":"test-sim-model","messages":[{"role":"user","content":" ".join(f"word{i}" for i in range(2000))}],"max_tokens":5,"stream":True,"stream_options":{"include_usage":True}}))' > /tmp/req.json

# 3. Send it twice. ttfb ≈ TTFT; the last line shows cached_tokens.
for i in 1 2; do
  curl -sN -w "\nrun$i ttfb=%{time_starttransfer}s\n" localhost:8000/v1/chat/completions \
    -H 'content-type: application/json' -d @/tmp/req.json | grep -E 'usage|ttfb'
done

# 4. Look at the cache metrics, then clean up.
curl -s localhost:8000/metrics | grep -E '^vllm:(prefix_cache|cache_config)'
docker rm -f tether-sim0
```

**Before you run it, predict:** the simulator's TTFT is `prefill_overhead + uncached_tokens × 1 ms`. The
prompt is 2,005 tokens and blocks are 64 tokens. What will `cached_tokens` be on run 2, and what TTFT?
(Hint: only *full* blocks are cached.) Then compare with what I measured in
[FINDINGS-M0.md](../FINDINGS-M0.md) §A2.

Things to try after: change one early word in the prompt and re-send (why does almost everything miss?);
change only the *last* word (why does almost everything still hit?). That is LEARNING.md §1.7 in action.

## Why things were done this way (plain language)

1. **Purity is enforced by clippy.**
   - SPEC §0.5 says `tether-core` must not read the clock or use randomness. A rule in a document is easy
     to break by accident; a lint that fails CI is not.
   - The clippy config bans `Instant::now`, `SystemTime::now`, `thread::sleep`, and also std `HashMap` /
     `HashSet`. Those two iterate in a different random order in every process, so a simulator that loops
     over a `HashMap` could give different results with the same seed.
   - I checked the ban works by adding a violation and watching clippy fail.
2. **CI actions are pinned to commit SHAs.** Someone can move a tag like `v7.0.1` to point at different
   code, but not a SHA. The same idea is why every downloaded file (traces, model, tools) was checked
   against a published SHA-256. See LEARNING.md §4.8.
3. **The gateway binds and workers dial in.**
   - vLLM can do either (bind if the endpoint has `*`); the sim can only dial.
   - One direction works for both, and one socket per worker tells us which worker an event came from.
   - The catch: a dialing publisher queues events while nobody is listening, so a restarted gateway gets
     old events. That's why the index de-duplicates by `seq` and `ts`, and is rebuilt from scratch on
     restart.
4. **In simulation, every trace gap is treated as a tool pause.**
   - The canonical traces have no labels, and on the labelled set gap length can't tell tool from user
     (p90 is 124 s for both).
   - Any heuristic would be a guess dressed up as data. "All tool" is right ≥ 87% of the time on the
     labelled set, and the 13% re-label run measures how much the answer changes if it's wrong.
5. **Client credentials are stripped by default.** In A5, Claude Code sent your OAuth token to a local
   vLLM because no dummy `ANTHROPIC_AUTH_TOKEN` was set. A gateway that forwards everything would do the
   same to every worker. Self-hosted workers never need the client's provider credentials.
6. **Normalization happens only for fingerprints.**
   - Tether strips Claude Code's per-session billing suffix before *hashing*, never before *forwarding*.
   - If the gateway rewrote prompts, it could change model output and the cache keys the engine computes.
     Then Tether would be measuring its own side effects.

## Open questions (need your decision before the M1 plan)

1. **More normalization rules from the Claude Code capture** (proposed spec change to §6.1.2).
   Fingerprints should:
   - drop `cache_control` (Claude Code moves it to the newest message every turn);
   - treat a plain-string `content` and a single text block as equal (older messages get re-serialized);
   - accept `role: "system"` messages inside `messages`.

   Without these, every turn looks like a prefix break.
2. **Compaction detection** (§6.1.2). The spec says "message count dropped sharply", but in the capture
   `/compact` made the count *rise* (6 → 7) and rewrote message 0. Proposal: compaction = explicit
   session id match + lineage break at message index ≤ 1, with the count only as a supporting signal.
3. **Subagent identity** (§6.1.2). Claude Code subagents send the **parent's** session id, with
   `cc_is_subagent=true` in the billing block. Proposal:
   - a request whose session id matches but that has `cc_is_subagent=true` and a different program
     becomes a **child session** of that parent (kind `fresh`);
   - the header-based rule sits beside the 10 s window rule.
4. **Retries** (§6.1.2 / §6.2.1). They're not marked by any header. Proposal: the same session and an
   identical request fingerprint within 60 s count as a retry of the same turn; don't count a new turn or
   a pause gap.
5. **Tool list changing mid-session** (25 → 266 tools after the first tool call, probably your MCP
   connectors). Nothing to change now; E7 should check whether it happens on a clean install. If it does,
   every such session has a full prefix break on turn 2.
6. **`kv_cache_report_mode: "full"`** (FINDINGS §A3). It's per-request, set via `vllm_xargs`, and costs
   ~3.1 bytes of event payload per reused token on every hit. Proposal for M4: a per-worker opt-in that
   the gateway injects only when the client didn't set `vllm_xargs`; default off.
7. **Two interpretations I chose that you should confirm:**
   - The 13% sensitivity re-label keeps the recorded gap durations and picks gaps by `P(user | gap)`
     from 042026.
   - Credential stripping applies to every worker `kind`, including `dynamo`, not just vllm/sglang/sim.
8. **One edit beyond the approved list:** in the usage commit I also wrote that a compressed upstream
   response is decompressed for the tee and forwarded unchanged (Anthropic sends gzip SSE; FINDINGS
   §A8). Keep it or drop it.

9. **OpenCode's subagent tool is `task` (lowercase)** and its side call shares the main session id
   (FINDINGS §A8). Proposal: match `subagent_tool_names` case-insensitively (§7), and note in §6.1.2
   that a shared session id does not rule out `Side`.
