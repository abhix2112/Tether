## Concepts in this milestone

M0 writes almost no product code. It checks that the outside world matches what SPEC.md assumes. These
are the concepts you need to follow what M0 finds (links go to [LEARNING.md](../LEARNING.md)):

| Concept | Why it matters in M0 | Learn it |
|---|---|---|
| Attention needs all earlier tokens | It explains why a KV cache exists at all | [§1.1](../LEARNING.md#11-transformers-and-attention) |
| Tokens and tokenization | The simulator uses a *simulated* tokenizer; we check whether "one word ≈ one token" holds, because the trace replay depends on it | [§1.2](../LEARNING.md#12-tokens-and-tokenization) |
| ⭐ Prefill vs decode, KV cache | Your hands-on task: send the same prompt twice and watch `cached_tokens` go up and TTFT go down | [§1.3](../LEARNING.md#13--prefill-vs-decode-and-the-kv-cache) |
| Chat templates and tool calling | The traffic capture records how Claude Code marks a tool call (`stop_reason: "tool_use"`) and how the tool result comes back | [§1.9](../LEARNING.md#19-chat-templates-and-tool-calling-the-wire-formats-tether-reads) |
| ⭐ Prompt caching in Claude Code | Ground truth for what the capture should show: stable prefix first, what breaks the cache, subagents vs forks | [§1.10](../LEARNING.md#110--prompt-caching-in-hosted-apis-and-how-claude-code-uses-it) |
| ⭐ Why agent traffic is different | The AgentX traces we download in M0 are where these numbers come from | [§2.6](../LEARNING.md#26--why-agent-traffic-is-different) |

**Your hands-on task (from LEARNING.md §8):** run the llm-d simulator, send one long prompt twice, and
watch `usage.prompt_tokens_details.cached_tokens` and time-to-first-token change. Exact commands will be
added below as soon as the simulator step is done.
